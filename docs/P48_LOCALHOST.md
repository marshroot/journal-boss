# P48: локальный запуск и роли

## Основной запуск через Docker Desktop

1. Скопируйте `.env.example` в `.env`.
2. Установите уникальный `JWT_KEY` (не менее 32 символов), `ADMIN_LOGIN` и сильный `ADMIN_PASSWORD`.
3. Из корня проекта выполните `docker compose up -d --build`.
4. Откройте `http://localhost:3000`.
5. Проверяйте состояние через `docker compose ps`, логи — через `docker compose logs --tail=100`.
6. Остановить сервисы: `docker compose down`. Данные сохраняются в Docker volumes.

Публичный домен, DNS, Caddy и HTTPS не используются основным compose. Порт frontend привязан к loopback-интерфейсу, поэтому сайт не публикуется напрямую в локальную сеть.

## Telegram-бот (необязательно)

Заполните `TELEGRAM_BOT_TOKEN` в `.env`, затем запустите `docker compose --profile telegram up -d --build`. Без этого профиля отсутствие токена не мешает старту портала.

## Куратор

По согласованному требованию куратор имеет те же права, что и родитель: просмотр прогресса, оценок, посещаемости и выполнения домашних заданий связанных детей. В текущей модели авторизации это каноническая роль `Parent`; отдельные дополнительные разрешения куратору не выдаются.

## SQLite-миграция объявлений

Для старой таблицы `announcements`, в которой отсутствует `is_published`, при запуске добавляется `INTEGER NOT NULL DEFAULT 1`. Это сохраняет существующие строки и делает их опубликованными по умолчанию. Не удаляйте `journal.db` для применения миграции.

## Ограничения проверки релиза

Статические проверки compose, контрактов и тесты Node выполнены. Полный `dotnet build`, frontend production build и `docker compose up` должны быть выполнены на машине с .NET SDK, доступом к npm registry и Docker Desktop; эти инструменты не были доступны/завершены в среде сборки этого архива.
