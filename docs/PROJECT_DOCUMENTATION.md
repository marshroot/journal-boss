# Jornal — документация проекта

Версия: **v23-P75**. Документ описывает обоснование системы, технические особенности
исполнения, требования к инфраструктуре и инструкции по работе для каждой роли.

---

## 1. Обоснование

### Назначение

Jornal — образовательный портал (электронный журнал) для учебных центров, школ и курсов:
единое место для расписания, ведения занятий, оценки знаний, домашних заданий, материалов,
общения и онлайн-обучения. Система заменяет разрозненные инструменты (бумажный журнал,
мессенджеры, таблицы, видеосвязь «через ссылку») одним защищённым контуром с ролями и аудитом.

### Какие проблемы решает

| Без системы | С Jornal |
|---|---|
| Расписание в таблицах/мессенджерах, «наезд» пар друг на друга | Единое расписание с автоматической проверкой пересечений у группы и преподавателя; перенос пар преподавателем |
| Оценки и посещаемость в бумажном журнале | Оценки, посещаемость и темы занятий сохраняются в БД, видны студенту и родителю онлайн |
| ДЗ пересылают в чатах, работы теряются | Жизненный цикл ДЗ: создание → сдача → проверка преподавателем → итоговая оценка; файлы заданий и работ хранятся в системе |
| Связь с родителями — по телефону | Родительский кабинет: успеваемость, посещаемость, ДЗ и расписание ребёнка, платежи |
| Онлайн-занятия через сторонние сервисы | Встроенная онлайн-пара на LiveKit: видео, микрофон, демонстрация экрана, управление участниками |
| Объяснение «на пальцах» или в отдельном графическом редакторе | Совместная доска (tldraw) с режимом трансляции: рисунок преподавателя выводится на экраны студентов автоматически |
| Проверка программ — вручную | Code Lab: Monaco-редактор, совместное редактирование (Yjs/Hocuspocus), запуск кода в песочнице Judge0 |
| Учёт оплаты — в тетрадке | Демо-платёжная система: счета, статусы, история (готова к подключению реального провайдера) |

### Целевая аудитория

- **администратор учебного центра** — управление пользователями, группами, предметами, расписанием, аудит и резервные копии;
- **преподаватель** — проведение занятий (аудиторных и онлайн), оценка, ДЗ, материалы, доска;
- **студент** — расписание, ДЗ, материалы, оценки, чат, онлайн-пара, Code Lab;
- **родитель** — наблюдение за успеваемостью и посещаемостью ребёнка, платежи.

### Почему такое решение

- **Self-hosted**: все данные (SQLite + файлы) остаются у владельца; нет зависимости от внешнего SaaS.
- **Docker Compose**: весь стек (backend, frontend, realtime-софт, LiveKit) разворачивается одной командой.
- **Открытые компоненты**: ASP.NET Core, React, SignalR, LiveKit (open-source SFU), Hocuspocus/Yjs,
  tldraw, Judge0, Monaco — без платных лицензий.
- **Модульность с деградацией**: внешние сервисы (LiveKit, Judge0) опциональны — без их настроек
  остальная система работает, а соответствующие функции возвращают понятную ошибку (503).

## 2. Технические особенности исполнения

### Стек и компоненты

| Компонент | Технология | Назначение |
|---|---|---|
| Backend | ASP.NET Core 9 (C#, `net9.0`), EF Core + SQLite | REST API `/api/*`, авторизация, бизнес-логика, аудит |
| Frontend | React 19 + TypeScript, Vite, Tailwind-стили, nginx | SPA; в проде отдаётся nginx и проксирует `/api`, `/hubs`, `/collab`, `/health` на backend |
| Realtime чат | SignalR (`/hubs/lesson-chat`) | Чат пары, личные сообщения, групповые чаты (текст + изображения) |
| Совместное редактирование | Hocuspocus + Yjs (сервис `collab`, порт 1234, SQLite-персистентность) | Code Lab (Monaco) и доска |
| Доска | tldraw + REST-синхронизация | Совместное рисование; режим трансляции: снимок доски обновляется у зрителей каждые 3 с |
| Онлайн-пара | LiveKit Server 1.13 (SFU, WebRTC) + `livekit-client` | Видео/аудио/демо экрана; токены участников выдаёт backend после проверки ролей |
| Запуск кода | Judge0 (внешний) | Песочница: CPU 2 с, wall-clock 5 с, память 128 МБ, сеть отключена, вывод ≤ 20 000 символов |
| Платежи | Демо-модуль (`provider = "example"`) | Счета, статусы Pending/Paid/Cancelled/Refunded; заменяется на webhook реального провайдера |

### Архитектурные решения

- **Монолит с явными границами**: 28 контроллеров по доменам (аутентификация, занятия,
  оценивание, файлы, чаты, онлайн-пара, платежи, админ-модули), один `AppDbContext`.
- **SQLite как основная БД** — осознанный выбор для нагрузки учебного центра (сотни
  пользователей): нулевое администрирование, файл в volume `journal_data`, простые бэкапы
  (встроенный модуль backup упаковывает БД, файлы, ключи и collab-хранилище).
- **Миграция схемы без EF Migrations**: `SqliteSchemaUpgrades` при старте приводит существующую
  БД к текущей модели (переименование legacy-колонок, создание недостающих таблиц/индексов,
  добавление колонок) — обновление версии не требует ручных действий с БД.
- **UTC везде**: конвертер `UtcDateTimeConverter` пишет/читает DateTime как UTC — расписание,
  чаты и дедлайны одинаково отображаются в любом часовом поясе клиента.
- **Аудит действий**: отдельный сервис пишет в `audit_logs` входы, оценки, изменения
  расписания, файловые операции, онлайн-пары, трансляции доски, платежи, backup.
- **Realtime-контур отдельным сервисом**: Hocuspocus не публикуется наружу напрямую — доступ
  только через nginx `/collab`; сервер проверяет подпись короткоживущего JWT (audience
  `JournalCollab`, привязка к комнате `collab_room`, срок действия).

### Безопасность

- Аутентификация — локальный JWT (issuer `JournalBackend`, audience `JournalFrontend`),
  срок по умолчанию **8 часов** (`Jwt:ExpiresMinutes`), ключ ≥ 32 символов из `JWT_KEY`.
- Роли: `Admin` / `Teacher` / `Student` / `Parent`; права проверяются на сервере в каждом
  эндпоинте (владение парой, принадлежность к группе, связь родитель→студент).
- Rate limiting: 300 запросов/мин на пользователя/IP; логин — 10 попыток/мин на IP; чат —
  20 сообщений/мин на пользователя.
- Файлы: загрузка только по белому списку типов с проверкой расширения (вложения до 25 МБ,
  изображения чата до 10 МБ), имена очищаются, ключи хранения — GUID; скачивание только через
  авторизованный API с проверкой path-traversal; storage не публикуется напрямую.
- Изображения чата доступны только участникам того чата, где отправлено сообщение.
- Доска: чтение/редактирование только участникам пары; права рисования управляет преподаватель.
- Онлайн-пара: токен LiveKit выдаётся после серверной проверки (владелец пары или студент
  группы), модераторские права — только у преподавателя/админа; завершение пары закрывает
  комнату и трансляцию доски.
- Внешние креденшалы legacy-интеграции шифруются ASP.NET Data Protection (`enc:v1:`).

### Известные ограничения

- 18 legacy-эндпоинтов Top Academy/Telegram ещё работают по `sessionToken` (вынесены в
  отдельный аудит, отключены по умолчанию без `APPLICATION_KEY`).
- JWT нельзя отозвать до истечения срока; удалённый пользователь сохраняет доступ до конца токена.
- Совместная доска синхронизируется опросом (3 с), а не CRDT; одновременное рисование
  нескольких пользователей возможно, но финальное состояние определяет последнее сохранение.
- Платёжный модуль — демонстрационный (без реального списания).

## 3. Требования для работы приложения

### 3.1. Сервер (хостинг)

**Операционная система.** Любая ОС с Docker Engine / Docker Compose; рекомендованы
**Linux-дистрибутивы: Ubuntu Server 22.04+/24.04, Debian 12** (образы сервисов — linux-контейнеры).
Windows-хост возможен через Docker Desktop (WSL2) либо локальный запуск без Docker через
`run.bat` (требует установленных .NET 9 SDK и Node.js 22 + npm). macOS не тестировалась,
но стек (.NET/Node) кроссплатформенный.

**Локация.**

- Сервер размещается как можно ближе к пользователям: целевая задержка **≤ 60–100 мс** до
  клиентов. Для учебных центров в РФ/СНГ — хостинг в соответствующем регионе.
- Для **онлайн-пар (LiveKit)** задержка критична: тот же регион, что и студенты; UDP не должен
  блокироваться провайдером/файрволом (порт 7882/udp + TCP 7880/7881 как fallback).
- Часовой пояс сервера не важен (все времена хранятся в UTC), важна синхронизация времени (NTP)
  — от неё зависят JWT, расписание и токены LiveKit.

**Ширина канала.**

| Сценарий | Расчёт | Рекомендация |
|---|---|---|
| Текстовые модули (журнал, ДЗ, чат, доска) | ~10–100 Кбит/с на активного пользователя | 10 Мбит/с хватает на 50–100 пользователей |
| Онлайн-пара: стримит преподаватель (видео + демо экрана) | ~2–4 Мбит/с исходящего трафика на сервер; ~2–3 Мбит/с входящего каждому студенту | Класс 30 чел.: аплинк сервера ≥ 10 Мбит/с, у каждого студента ≥ 3–4 Мбит/с down |
| Онлайн-пара с видео у всех участников | SFU: сервер отдаёт ~1,5–2,5 Мбит/с × участников на каждый активный поток | Для групп > 15–20 включать видео выборочно или выделить LiveKit-инстанс с соответствующим аплинком |
| Загрузка файлов | до 25 МБ на файл (изображения чата до 10 МБ) | Учесть пиковые загрузки материалов к парам |

**Системные требования (сервер).**

| Компонент | Минимум | Комфортно (до ~100–300 активных пользователей, текстовые модули + периодические онлайн-пары) |
|---|---|---|
| CPU | 2 vCPU | 4 vCPU |
| RAM | 2 ГБ | 4–8 ГБ (backend ~0,5–1 ГБ, collab ~0,3 ГБ, LiveKit ~1 ГБ под нагрузкой) |
| Диск | 10 ГБ | SSD 20+ ГБ (БД, вложения, collab-хранилище растут по мере использования) |
| ПО | Docker Engine + Docker Compose v2 | — |
| Сеть | открытые TCP 80/443 (прокси) и 3000 (локально), 7880/7881 TCP + 7882/udp для LiveKit | TLS-терминация через внешний Caddy/Nginx (файл `Caddyfile` прилагается как пример) |

Внешние сервисы (опционально): Judge0 (например, `http://host.docker.internal:2358`),
LiveKit (по умолчанию поднимается в compose). Ничего внешнего обязательного нет.

### 3.2. Клиент (рабочее место пользователя)

- **Браузер** с поддержкой WebSocket и WebRTC: актуальные Chrome, Edge, Firefox, Opera, Safari
  (для онлайн-пар и совместного редактирования желательны Chrome/Edge).
- **ОС**: любая (Windows 7+, macOS, Linux, Android/iOS — интерфейс адаптирован под мобильные).
- **Устройство**: для онлайн-пар — веб-камера/микрофон, ≥ 3–4 Мбит/с канала; для остальных
  модулей — любой компьютер/планшет/смартфон.
- Доступ: URL сервера (по умолчанию `http://localhost:3000`), логин и пароль, выданные администратором.

### 3.3. Переменные окружения (`.env`, ключевые)

| Переменная | Обязательна | Описание |
|---|---|---|
| `JWT_KEY` | да | Секрет JWT ≥ 32 символов |
| `ADMIN_LOGIN` / `ADMIN_PASSWORD` | да | Первый администратор (создаётся, если в БД нет пользователя с таким логином) |
| `CORS_ORIGIN` | нет | По умолчанию `http://localhost:3000` |
| `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` / `LIVEKIT_PUBLIC_URL` / `LIVEKIT_SERVER_URL` | для онлайн-пар | Ключи и адреса LiveKit; без них API вернёт 503 только для онлайн-функций |
| `JUDGE0_URL` | для Code Lab | Адрес песочницы Judge0 |
| `LIVEKIT_TOKEN_TTL_SECONDS` | нет | Время жизни токена участника (300–86400, по умолчанию 7200) |
| `APPLICATION_KEY` | нет | Только для legacy Top Academy-интеграции; пустая = интеграция выключена |

## 4. Инструкция по применению (по ролям)

Вход: открыть адрес портала → страница **«Вход»** → ввести логин/пароль. Роль определяет
доступные разделы бокового меню. Общие для всех разделы: **Главная, Расписание, Оценки,
ДЗ, Материалы, Сообщения, Платежи (демо), Объявления, Награды, Личный кабинет, FAQ,
Контакты, Обращения, Жалобы**.

### 4.1. Администратор

Первый вход — по `ADMIN_LOGIN`/`ADMIN_PASSWORD` из `.env`.

1. **Пользователи** (`Панель администратора → Пользователи`): создание и управление
   учётными записями студентов, преподавателей, родителей; закрепление студентов за группами,
   связывание родителей со студентами; сброс паролей.
2. **Учебная структура** (`Учебная структура`):
   - создать **группы** и **предметы**;
   - за каждым предметом **закрепить преподавателя** (обязательное условие для расписания);
   - **расписание**: добавление/редактирование/удаление пар. Система не позволит поставить
     две пары одной группе или одному преподавателю на пересекающееся время (409 с указанием
     конфликтующей пары). Удаление пары с оценками/ДЗ/материалами требует подтверждения.
   - время вводится в вашем часовом поясе и хранится в UTC.
3. **Аудит и backup** (`Аудит и backup`): журнал действий (входы, оценки, изменения
   расписания, файлы, платежи, онлайн-пары, трансляции доски); создание и восстановление
   резервных копий (БД + файлы + collab + ключи) на одноразовом инстансе.
4. **Платежи**: вкладка «Все пользователи» — все счета и статусы; доступен возврат
   оплаченного платежа.
5. Администратор также может всё, что может преподаватель (ведение пар, онлайн-пары, доска).

### 4.2. Преподаватель

1. **Мои занятия** (`Мои занятия`): список ближайших пар. Открытие пары даёт:
   - **тема занятия** — сохраняется и сразу видна студентам;
   - **время проведения** → «Перенести пару»: изменить начало/окончание/аудиторию;
     система проверит отсутствие пересечений у вас и у группы (начатую пару можно только
     продлить по времени, завершённую — нельзя переносить);
   - **посещаемость** (4 статуса, «Отметить всех присутствующими»);
   - **оценки** 0–10 с комментарием, одной кнопкой на всю пару;
   - **домашнее задание**: создание (название, условие, срок) + файлы задания;
     проверка сданных работ, итоговая оценка и комментарий (после итоговой оценки повторная
     сдача студенту закрыта);
   - **онлайн-пара**: «Начать онлайн-пару» → «Открыть трансляцию»; управление участниками
     (заглушить одного/всех, отключить участника, попросить демонстрацию экрана).
2. **Текущая пара** (`Текущая пара`) — единый экран идущей пары: начать/завершить пару, тема,
   посещаемость, оценки, ДЗ, материалы, онлайн-пара и **доска**:
   - «Включить доску и показать всем» — доска откроется у студентов группы автоматически;
   - «Остановить показ» или завершение пары выключает трансляцию.
3. **Доска** (`Доска`): рисование, автосохранение; кнопка «Права» — кому можно рисовать
   (только просмотр / рисуют все студенты / выбранные); кнопка «Показать доску всем».
4. **Чат пары** и **Сообщения**: обмен сообщениями и **изображениями** (PNG/JPEG/WebP/GIF
   до 10 МБ) со студентами и коллегами; создание групповых чатов.
5. **Материалы** (`Материалы`): конструктор материалов (TipTap), статус черновик/опубликован
   (студенты видят только опубликованные), файлы к материалам.
6. **Code Lab**: задачи с кодом, просмотр submissions студентов; совместное редактирование.

### 4.3. Студент

1. **Расписание**: свои пары на неделю; «текущая пара» определяется автоматически.
2. **Текущая онлайн-пара** (`Текущая онлайн-пара`): во время пары —
   «Подключиться к онлайн-паре» (видео/аудио, демонстрация экрана по запросу преподавателя);
   когда преподаватель включает доску, секция **«Преподаватель показывает доску»** появляется
   автоматически и обновляется каждые 3 секунды (доску можно свернуть; если преподаватель
   разрешил — можно рисовать вместе).
3. **ДЗ**: список заданий своей группы, файлы задания, сдача ответа (до выставления итоговой
   оценки), просмотр оценки и комментария преподавателя.
4. **Оценки**: свои оценки по предметам; **Материалы**: опубликованные материалы пары с файлами.
5. **Сообщения** и **Чат пары**: личные сообщения и групповые чаты с преподавателями и
   одногруппниками, отправка изображений.
6. **Code Lab**: решение задач (Monaco), отправка на проверку, совместное редактирование,
   просмотр результата выполнения в песочнице.
7. **Платежи (демо)**: свои счета и демо-оплата.
8. Дополнительно: объявления, награды, FAQ, обращения, редактор изображений.

### 4.4. Родитель

1. **Кабинет родителя** (`Кабинет родителя`): сводка по ребёнку; при нескольких детях —
   переключение между ними.
2. **Прогресс ребёнка**: оценки и домашние задания выбранного ребёнка (только просмотр).
3. **Посещаемость ребёнка**: статусы посещаемости по парам.
4. **Расписание**: пары ребёнка.
5. **Сообщения**: связь с преподавателями и администрацией (текст и изображения).
6. **Платежи (демо)**: создание счетов, в том числе **за ребёнка** (платить можно только за
   связанного ребёнка), демо-оплата и отмена неоплаченных счетов.

