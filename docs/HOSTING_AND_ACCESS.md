## 1. Требования для хостинга

### Операционная система

| Вариант | ОС | Комментарий |
|---|---|---|
| Рекомендуемый (прод) | Linux: **Ubuntu Server 22.04/24.04, Debian 12** | запуск через Docker Compose; образы — linux-контейнеры |
| Windows-хост | Windows 10/11, Windows Server | Docker Desktop (WSL2) — те же контейнеры |
| Без Docker (разработка) | Windows | `run.bat`: требует установленных .NET 9 SDK и Node.js 22 + npm |

### Ресурсы (CPU / RAM)

| Режим | vCPU | RAM |
|---|---|---|
| Минимум (демо, до ~20 пользователей) | 2 | 2 ГБ |
| Рекомендуемо (до ~100–300 активных пользователей: журнал, ДЗ, чаты, доска, периодические онлайн-пары) | 4 | 4–8 ГБ |

Ориентация по сервисам: backend (ASP.NET Core) ~0,5–1 ГБ; collab (Hocuspocus) ~0,3 ГБ;
frontend (nginx) — незначительно; LiveKit ~1 ГБ под видеонагрузкой. Judge0 (опционально) —
отдельный контейнер/сервер, рекомендация его производителя — 2+ vCPU.

### Объём диска

| Назначение | Объём |
|---|---|
| Система + Docker + образы | 10 ГБ |
| Рабочий объём (SQLite `journal.db`, вложения до 25 МБ/файл, изображения чата до 10 МБ, collab-хранилище) | SSD 20+ ГБ с запасом на рост |
| Бэкапы (модуль backup: БД + файлы + ключи) | + объём данных × число хранимых копий |

Docker volume'ы с данными: `journal_data`, `journal_uploads`, `collab_data`.

### Сеть и порты

| Порт | Протокол | Назначение |
|---|---|---|
| 3000 | TCP | Веб-интерфейс (nginx; в compose по умолчанию привязан к `127.0.0.1:3000` — для внешнего доступа изменить на `3000:80` или поставить обратный прокси на 80/443, пример — `Caddyfile`) |
| 7880, 7881 | TCP | LiveKit (сигналинг и WebRTC-over-TCP) |
| 7882 | UDP | LiveKit WebRTC-медиа (не блокировать файрволом) |
| 80/443 | TCP | Опционально: обратный прокси/TLS перед портом 3000 |
| 2358 | TCP | Judge0 (опционально, внешний/локальный) |

Канал: текстовые модули ~10–100 Кбит/с на пользователя; онлайн-пара — исходящий трафик
сервера ~2–4 Мбит/с на транслируемый поток, у студента ~3–4 Мбит/с входящего.
Локация — регион пользователей (задержка ≤ 60–100 мс), обязательна синхронизация времени (NTP).

## 2. URL — адреса

### Локальный запуск (текущая сборка, значения по умолчанию)

| Сервис | Адрес |
|---|---|
| **Веб-интерфейс (основной вход)** | **http://localhost:3000** |
| REST API | http://localhost:3000/api/* (тот же origin через nginx; вне Docker — http://localhost:5000/api/*) |
| Health-check | http://localhost:3000/health |
| SignalR-хаб чатов | http://localhost:3000/hubs/lesson-chat (WebSocket) |
| Совместное редактирование (collab) | http://localhost:3000/collab (WebSocket, проксируется в сервис :1234) |
| LiveKit (онлайн-пары) | ws://localhost:7880 (публичный URL `LIVEKIT_PUBLIC_URL`) |
| Judge0 (Code Lab) | http://localhost:2358 (`JUDGE0_URL`; при Docker на Windows — `http://host.docker.internal:2358`) |

### Публичный доступ

Система не привязана к домену. Для публикации: указать `CORS_ORIGIN` на адрес сайта,
`LIVEKIT_PUBLIC_URL` — на публичный wss-адрес LiveKit, пробросить порт 3000 (или поставить
Caddy/Nginx с TLS по образцу `Caddyfile`), после чего адресом становится
`http(s)://<ваш-домен>`.

## 3. Данные для входа / авторизации

### Первый администратор (создаётся автоматически при первом старте)

| Параметр | Значение |
|---|---|
| Логин | `admin` |
| Пароль | задаётся в `.env` → `ADMIN_PASSWORD` (в локальной копии `.env`; сам файл в репозиторий не входит) |
| Где задаётся | `.env` → `ADMIN_LOGIN`, `ADMIN_PASSWORD` (создаётся только если пользователя с таким логином ещё нет в БД; смена значения в `.env` существующего пользователя **не** меняет) |
| Сменить пароль | раздел «Пользователи» в панели администратора |

> ⚠️ Реальные значения лежат только в локальном `.env` (файл перенесён из дерева проекта в
> `jornal-private-backup` и в `.gitignore`). Перед внешним доступом — сменить пароль
> администратора и заменить `JWT_KEY` на новый случайный секрет (≥ 32 символов).

### Остальные пользователи

- Учётные записи преподавателей, студентов и родителей создаёт **администратор**
  («Панель администратора → Пользователи»); там же сброс паролей и связки
  «студент → группа», «родитель → студент».
- Вход для всех ролей — кнопка «Вход» на главной странице (`/login`).
- Авторизация — локальный JWT (срок 8 часов), передаётся в заголовке `Authorization: Bearer`;
  ключи LiveKit и collab-токены выдаются сервером автоматически после проверки роли.

### Секреты конфигурации (`.env`, локальной копии)

| Переменная | Назначение |
|---|---|
| `JWT_KEY` | подпись JWT (генерируется свой, ≥ 32 символов; в репозитории только шаблон `.env.example`) |
| `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` | для локальной разработки — публичная пара `devkey`/`secret` (совпадает с `livekit/config.yaml`); для прода — свои ключи |
| `APPLICATION_KEY` | legacy Top Academy-интеграция; пусто = выключена |

## 4. Исходный код проекта

### Расположение

| Что | Где |
|---|---|
| Проект | корень репозитория (клонируется целиком) |
| Удалённый репозиторий | **отсутствует** — проект пока не под версионным контролем (нет `.git`) |

### Структура проекта

```
jornal/
├── backend/JournalBackend/       # ASP.NET Core 9: API, SignalR-хаб, EF Core + SQLite
│   └── JournalBackend.Tests/     # xUnit-тесты (17)
├── frontend/                     # React 19 + TS + Vite; e2e (Playwright), tests (node:test, 32)
│   └── src/pages, components, lib
├── collab/                       # Hocuspocus + Yjs (совместное редактирование Code Lab)
├── livekit/                      # конфиг локального LiveKit (публичный devkey)
├── scripts/                      # контрактные проверки, smoke-тесты, аудит релиза
├── docs/                         # документация (README.md — индекс)
├── docker-compose.yml            # прод-контур: livekit, backend, collab, frontend
├── run.bat / start.bat           # локальный запуск на Windows
├── Caddyfile                     # пример TLS-прокси для публикации
├── VERSION                       # v23-P75
└── CHANGELOG_P74.md, CHANGELOG_P75.md
```

Локальные данные (не входят в репозиторий, создаются при работе): `database/` (SQLite-БД),
`storage/` (загруженные файлы), `.env`, `frontend/dist`, `node_modules`.

### Публикация в репозиторий (Git не инициализирован — сделать один раз)

```bash
git init
# создать пустой репозиторий на GitHub/GitLab и скопировать его URL, затем:
git remote add origin <URL-репозитория>
git add .
git commit -m "Jornal v23-P75"
git push -u origin main
```

Перед первым пушем убедиться, что не попадают приватные файлы: `.env`, `database/*.db`,
`livekit/server.log`, `journal_data.json` (правила уже есть в `.gitignore`; коммитить
`.env.example`, а не `.env`). После появления удалённого репозитория — вписать его URL
в этот раздел и в `README` проекта.

### Сборка и проверка из исходников

```bash
# backend
cd backend/JournalBackend && dotnet build && cd ../JournalBackend.Tests && dotnet test
# frontend
cd frontend && npm ci && npm run lint && npm test && npm run build
# полный контур
docker compose up --build     # http://localhost:3000
```

CI: `.github/workflows/ci.yml` (4 job'а: backend, frontend, docker, integration-contracts) —
заработает после пуша в GitHub.
